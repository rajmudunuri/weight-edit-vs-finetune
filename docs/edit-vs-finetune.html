Editing DistilBERT's weights by hand vs fine-tuning it

Long image

A

Answer

On this small model, fine-tuning fixed the negation failure better: 64–67% versus 58.5% on unseen phrasings, with far less damage to real reviews. The hand-written weight edit still has its uses. It changed only 49,920 weights, needed one forward pass and no gradients, and every change has a stated reason.

  1. The model misreads implicit negation: "The plot was anything but dull" comes out negative. Test accuracy on such sentences is 46.5%.
  2. A gradient-free edit to 64 columns of one layer lifted unseen phrasings to 58.5%, but real-review accuracy fell from 91.1% to 83.8%.
  3. Fine-tuning on the same examples reached 63.8–66.7% and kept real-review accuracy near 89.5%, in 5–13 seconds on a MacBook.
  4. No method learned implicit negation in general. Like the post's Gemma result, editing only rewires what the model already has.1

  2. Read activations ↗

    Forward passes on dev sentences only. They show where explicit "not" flips sentiment and why implicit cues miss it.

  3. Write weight edit ↗

    A closed-form key-to-value rule written into one FFN layer. No loss, no optimizer.

  4. Fine-tune ↗

    Gradient descent on the same 2,592 dev examples: head only, LoRA, or every weight.

  5. Hidden test sets ↗

    Test sentences use cue phrasings and adjectives that dev never shows. Real text comes from the 872 SST-2 validation reviews.3

Where does negation break inside the model?

Explicit negation works. "The plot was not dull" is flipped to positive in block 4 of 6, where the "not" token's feature meets the adjective.

Implicit cues mostly do not write that "not" feature. "far" (as in "far from") does, and the model gets "far from good" right 100% of the time. "but", "nobody" and "opposite" barely do, so their sentences stay unflipped.

What exactly does the weight edit write?

The edit adds one rule to the feed-forward layer of block 1, in the style of ROME's rank-one edits.4 If a token looks like an implicit cue, the rule adds the "not" direction.

  • Key: the 64 of 3,072 hidden neurons that fire most specifically on cue tokens, compared with ordinary tokens in templates and real reviews.
  • Value: the difference between a "not" token and a cue token in the residual stream.
  • Write: those 64 columns of the output matrix get value × keyᵀ, scaled by strength 8. The bias is shifted so ordinary tokens stay unchanged on average.

Block, neuron count and strength were chosen on dev, with each cue held out in turn. The search took about 250 batched forward passes. Fitting the chosen edit took 1 forward pass and 1.5 seconds.

The random edit changes nothing, so edit v2's gain comes from the chosen direction, not from noise. Edit v1 used only template guards and broke real reviews, because "but" is common in real text. Edit v2 added real reviews to the dev-side guard.

Test was viewed twice for the edit

Edit v1 was scored on test once. Edit v2 then changed only dev-side inputs (a real-text guard), and was scored once more. Treat edit v2 as a second look, not a pristine first result. Fine-tune settings were standard values and were not tuned on test.

Use an edit when the failure has a clear mechanism, the model is too large or locked to train, or the change must be auditable. Use fine-tuning when you have labelled examples and want the best fix per hour of your time.

What does this not show?

  • Results cover one model, one failure and template sentences. Real implicit negation is more varied.
  • Claude wrote the edit in this session without a fixed budget. The post gave its LLM editor a fixed forward-pass budget.1
  • Fine-tuning used standard learning rates without tuning. Tuning could raise it further.
  • Each method saw the same data: 2,080 template sentences plus 512 real SST-2 train sentences.
